# Interrogate review of v2 (a30a7be..92f0c38)

Four reviewers on different models (opus, fable, sonnet, haiku) reviewed the LangChain/LlamaIndex plugins, the auto-sweep, and the near-tie rule, read-only. Models that raised each finding are in brackets. "Confirmed" means a probe script or failing scratch test reproduced it.

## Act on

Capture, hooks, store (owner P):

- **P1. Wrapper and custom framework retrievers lose top_k** [opus confirmed, sonnet confirmed]. Now that `BaseRetriever.invoke` is hooked, a retriever with no knob of its own (a custom `BaseRetriever` over a hooked chromadb collection, or a wrapper holding a `base_retriever`) owns the event and refuses top_k, while the inner hooked call could apply it. Under 0.2.0 this worked. Fix: the outermost hooked retrieval still owns the event and transforms, but top_k ownership passes to the outermost hooked retrieval that can apply it (for example a pending-top_k context variable the inner call consumes). Refuse only when no layer can apply it.
- **P2. A caller's `invoke(q, k=1)` defeats the override and the event lies** [fable confirmed]. `VectorStoreRetriever` merges call kwargs over `search_kwargs`. Fix by giving the codec the bound call arguments: one `override_top_k(args, top_k) -> Restore | None` method on the retrieval codec, argument behavior implemented once, framework codecs overriding it and also overriding a per-call `k`. The params snapshot must record what was actually applied.
- **P3. Schema migration is not atomic or idempotent** [all four, confirmed]. `executescript` commits per statement, so a crash between steps leaves a database that fails every later open with "duplicate column name". Fix: each migration step checks `PRAGMA table_info` before `ALTER`, and the version bump happens in the same explicit transaction (`BEGIN IMMEDIATE`, re-read `user_version` inside it).
- **P4. `_override_attr` records the knob before `setattr` succeeds** [haiku, fable confirmed]. A failed `setattr` leaks a depth entry and a later restore is skipped. Fix: `setattr` first, then record; clear `_knobs` in `reset_process()` and `uninstall_all()`.
- **P5. Params snapshot runs outside the recording-error guard, after the override** [sonnet, read]. Wrap it so a snapshot failure falls back to `{}` and can never leave a knob overridden.
- **P6. `init()` imports LangChain and LlamaIndex on every call** [haiku, timed 7.7 s and 2.8 s]. In production mode, hook a framework only if its module is already in `sys.modules` at `init()` time, and document "call `init()` after importing your framework". CLI mode keeps hooking everything it can import.
- **P7. A retriever that overrides `invoke` and calls children records one event per child** [sonnet, simulated]. Document the limit in README Limits.

Sweep, CLI, UI (owner Q):

- **Q1. One inapplicable candidate aborts the whole sweep** [opus, fable confirmed, sonnet confirmed]. Catch `InterventionNotApplicable` per candidate, drop it and later candidates on the same knob, record "not applicable: reason" in the report and print it. Always save a report, including on early exit (a `finally` with the reason).
- **Q2. Holdout labels choose the candidates** [opus]. Split first, then count labels from tune cases only, so the holdout really is unseen by the search.
- **Q3. Round 2 builds on a setting that only tied the baseline** [haiku, fable]. Stop when no candidate beats the baseline. Pick the round-2 base with the same rule as the final pick.
- **Q4. Near-tie ordering** [fable, opus]. Key becomes (tokens, -passed, latency). When token counts are unknown (zero) on the contenders, the window is 0 and the line says why.
- **Q5. Empty holdout from rounding** [haiku]. If a holdout was requested but rounds to zero cases, do not recommend; say why. An explicit `--holdout 0` stays an opt-in that prints "unconfirmed".
- **Q6. Source run** [haiku, sonnet, opus]. Use the newest baseline run that has diagnoses, name it in the output, and add `--run ID`.
- **Q7. Cost estimate recomputes the plan's shape by hand** [opus, fable]. Derive the graded-case list from the plan, one source.
- **Q8. Dashboard fails on a bad or missing report** [sonnet, opus]. Render each experiment independently; a report that does not parse shows the experiment without a recommendation. Move `SweepReport` parsing and the recommendation line where `_ui` does not import the runner.
- **Q9. Make the final decision a pure function over the experiment table** [haiku, opus, fable]. `decide(table, runs, held, window) -> outcome`, tested on its own. Remove the duplicated `beats()` guarantee.

## Consider (deferred)

- Simplify the policy machinery (`Scaled`, `Fixable`/`Unfixable`) [haiku]. Behavior-neutral; revisit when the policy grows.
- Store a structured outcome instead of prose in `SweepReport.reason` [haiku]. Partly covered by Q9.
- Split `split_cases` rounding rule documentation [haiku, sonnet]. Note in the docstring.

## Agreement

All four found the migration bug. Three found the sweep abort. Two independently found the wrapper-retriever regression, which shows the outermost-owns rule needed a top_k exception from the start. No reviewer disputed another.
