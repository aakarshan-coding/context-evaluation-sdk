# Interrogate review of v1 (commit 60f248b)

Four reviewers on different models (opus, fable, sonnet, haiku) reviewed the whole package read-only. Each finding below was confirmed by a probe script unless marked "read". Models that raised it are in brackets.

## Act on

Capture and hooks (owner X):

- **X1. `init()` must never raise** [opus, fable, sonnet]. Non-ImportError library import failures, unwritable project dir, schema-version mismatch, and `inspect.signature` errors all propagate into the user's app. `init()` must catch everything, log once, report a failed status in `InstallReport`, and leave hooks pass-through.
- **X2. Production buffer leaks and bleeds across requests** [all four]. The ambient buffer is cleared only by a successful hooked LLM call. Retrieval-only requests, unhooked LLMs, and failed LLM calls leave events that the next request's trace inherits, with the wrong question; the buffer grows without bound. Fix: bound the buffer, clear it in a `finally` around the LLM call, and do not attribute stale events to a later request.
- **X3. Production sink blocks the request and is fork-unsafe** [opus, fable, sonnet]. A synchronous SQLite commit under a lock on the caller's thread stalls the LLM call about 5 s when the DB is locked (measured 5.56 s). The connection opens at `init()` and is inherited across `fork()`. Fix: bounded in-memory queue drained by one daemon writer thread, drop and count when full, connection opened lazily and re-opened when `os.getpid()` changes, short busy timeout.
- **X4. `@retriever` consumes one-shot iterables** [fable, sonnet]. A generator result is exhausted by `decode`, and the user gets an empty result even with no intervention, in production too. Fix: materialize non-sequence iterables and return the materialized list, or refuse to hook non-`Sequence` results (log once, pass through untouched). A `Mapping` or `str` result must not be decoded as chunks.
- **X5. `InterventionNotApplicable` swallowed by the app's own `except Exception`** [fable, sonnet]. The experiment row then silently reports baseline behavior, which graft 3 forbids. Fix: record the error on the `ActiveRun` before raising, and have `execute` raise it after `answer()` returns however the exception travelled.
- **X6. Cost 0.0 when usage is missing** [all four]. `finalize_trace` prices `tokens or 0`, while token totals use the estimate. Fix: price the same resolved token counts, or return None when any call lacks usage. Also strip a date suffix from model ids before the price lookup (`gpt-4.1-mini-2025-04-14`).
- **X7. `pinecone_text_key` ignored under the CLI** [opus, fable]. The CLI installs first with the default key and a later `init(pinecone_text_key=)` is discarded as "already". Fix: the codec reads the key from process state at call time, and the CLI takes it from `config.json`.
- **X8. Worker threads lose the active run** [haiku]. `ContextVar` does not propagate into `ThreadPoolExecutor` workers, so retrievals there are not recorded and interventions do not apply. The CLI runs one question at a time (plan item 7), so in CLI mode fall back to a process-level current-run slot set by `active_run`.
- **X9. `@retriever` on a method picks `self` as the query** [fable]. Skip `self` and `cls`.
- **X10. `load_app` raises `SystemExit` from the runner** [fable]. Raise a runner error the CLI turns into a `UserError`.

Text, diagnosis, CLI, UI (owner Y):

- **Y1. Matching ignores word boundaries** [all four]. `answer_matches("4", "It takes 14 days")`, `answer_matches("No", "I do not know")`, `contains_evidence("bathe catalog", "the cat")`, and in-prompt chunk checks all match inside words. Short expected answers pass the fast path wrongly and skip the LLM grader. Fix: match whole-token sequences everywhere (`answer_matches`, the exact branch of `contains_evidence`, `in_prompt_pairs`).
- **Y2. `locate_gold` is wrong in three ways** [opus, fable, sonnet]. (a) It checks the whole prompt, which includes the question, so a question that repeats evidence words gives IN_PROMPT with no gold chunk. (b) Evidence split about 50/50 across two chunks gives IN_PROMPT with `gold=()`, so `GoldToTop` is a no-op and `OnlyGold` drops everything, and the case is mislabeled `not_context`. (c) It reads only `delivered`, so on an experiment run a setting that dropped gold reports `not_retrieved`. Fix: decide gold per delivered chunk, with adjacent delivered chunks joined when neither alone holds the evidence (both become gold); IN_PROMPT when a gold chunk is in the prompt; DROPPED when gold is delivered but not in the prompt, or retrieved but not delivered; NOT_RETRIEVED otherwise. Never use the question text as evidence of gold.
- **Y3. Ladder steps that change nothing still decide labels** [opus, fable, sonnet]. If gold is already first, `GoldToTop` is a second baseline rerun and a chance pass becomes `ignored`; `OnlyGold` with no other chunks likewise. Fix: skip a step whose transform is the identity on the baseline's delivered chunks, and record the skip.
- **Y4. Streamed production answers are stored as "" and judged** [opus, sonnet]. Skip traces with no answer text in judging (count them) instead of paying the judge to label an empty answer.
- **Y5. `cmd_run` saves the app spec before it loads** [opus, fable, sonnet]. Save only after `load_app` succeeds.
- **Y6. UI handler errors drop the connection** [opus, sonnet]. Return a JSON 500. The list view also shows "ungraded" for judged production traces [fable]; show the judge badge.
- **Y7. OpenAI provider sends `temperature` and `max_tokens` to reasoning models** [opus, fable]. For `gpt-5*` and `o*` models use `max_completion_tokens` and omit temperature.
- **Y8. `test_trace_schema_rejects_graded_without_case` tests the wrong constraint** [fable]. It fails on the foreign key, not the CHECK. Exercise the CHECK with a raw insert.
- **Y9. Small data-boundary fixes** [sonnet, opus]. CSV import strips a UTF-8 BOM; `build_tests` upserts per passage so a mid-run provider error keeps paid cases.

## Consider

- One shared row-rebuild helper for the three codecs [opus, fable]. Real duplication, but behavior-neutral. Deferred.
- Case id excludes the expected answer, so a re-import with a new answer overwrites history [sonnet]. Deferred; documented.
- Single-sample replays under a nondeterministic model [sonnet]. Y3 removes the worst case; multi-sample replays are a v2 question.

## Noted

- Two `RunSummary` types with different fields [opus, fable]. Rename the store one while touching it if cheap.
- Denormalized `in_prompt` column [fable]. Works; not worth churn now.
- `init()` creates no `.gitignore` for `.contexteval/` [sonnet]. README note.

## Agreement

All four models independently found the matching, buffer, and cost defects, which makes them the highest-signal items. Three found `init()` and the sync write. No reviewer disputed another's finding. The pattern says the suite tested the planted happy paths well and missed boundary inputs: short answers, threads, generators, failures inside the user's code, and production traffic shapes.
